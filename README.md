# Tools4Market

Free, browser-based marketing, SEO and AI-search tools. **30 tools live**, no signup, no limits, nothing uploaded — every tool runs 100% client-side.

Static site generated by a single Node script. No frameworks, no npm dependencies, no database, no API keys. Hosting cost: ₹0. Deployed to **Cloudflare Pages** — the static pages are the frontend, and one tiny serverless function (`/api/fetch`) is the backend that lets the tools read a customer's live URL without CORS.

- **Source:** [github.com/glixtron/tools4market](https://github.com/glixtron/tools4market) (private) — MIT licence · live at **https://www.tools4market.online**

## Build & preview

```bash
node build.mjs        # or: npm run build   → regenerates dist/
npm run serve         # → node serve-dev.mjs (static + /api/fetch proxy on port 8090)
```

Then open <http://localhost:8090>.

`serve-dev.mjs` is a zero-dependency Node server that mirrors production: it serves `dist/` **and** implements the same `/api/fetch?url=…` proxy (and SSRF guard) as the Cloudflare Pages Function, so the "Analyze your own page" URL mode works locally exactly like it will after deploy. A plain static server (`python3 -m http.server`, `npx serve dist`) also works — the URL panel then degrades gracefully to its paste-HTML path.

> Keep port **8090** as the canonical dev URL (test harnesses and docs assume it). If it's busy: `PORT=8091 npm run serve`.

**Rules:**
- `dist/` is **generated — never hand-edit it**. Change files under `src/`, then rebuild.
- After any change to `src/`, run `node build.mjs` (see rules.md §6).

A clean build prints:

```
✔ Built 31 HTML pages (20 tools, 4 categories, 5 policy pages) + sitemap.xml, robots.txt, 404.html, assets.
```

The build also warns if any page's `<title>` exceeds 60 characters or its meta description exceeds 158 — fix the data file rather than ignoring the warning.

## Adding a new tool

Two edits — one data definition, one runtime function — then rebuild. The build auto-lists the tool on the homepage, its category page, the related-tools sidebar and the sitemap.

### 1. Data definition (build-time)

Add an object to the matching category file in `src/data/` (`seo.js`, `ai-search.js`, `content.js` or `web.js`):

```js
{
  slug: 'word-counter',                 // URL becomes /tools/word-counter/
  name: 'Word Counter',
  cat: 'content',                        // must match a CATEGORIES id in src/data/index.js
  icon: '🔢',
  card: 'Count words, characters and reading time instantly.',
  keywords: 'word counter character count reading time',
  h1: 'Free Word Counter — No Signup, No Limits',           // pattern required by rules.md
  metaTitle: 'Free Word Counter — Words, Chars & Read Time', // ≤60 chars
  metaDesc: 'Count words, characters, sentences and…',       // ≤158 chars
  intro: 'One-line summary shown under the H1.',
  sections: [                            // ≥2 unique sections, hand-written
    { h: 'What it does', p: ['Paragraph one…', 'Paragraph two…'] },
    { h: 'How to use it', p: ['Steps…'] },
  ],
  faqs: [                                // 3–5 questions → FAQPage schema, auto-added
    { q: 'Is it free?', a: 'Yes — every tool on this site is free.' },
  ],
  html: `
${f.textarea('wc-text', 'Your text', 'Paste or type here…', 6)}
${outputArea('wc-out', 'Counts')}`,     // helpers: f.text/url/textarea/select/number/date/check, outputBlock, outputArea, note
},
```

Every user-facing string lives in these data files — never hardcode copy inside runtime files (rules.md §3).

### 2. Runtime logic (client-side)

Register an init function in the matching `src/runtime/*.js` under the same slug:

```js
T['word-counter'] = function (root) {
  var out = $(root, 'wc-out');
  function update() {
    var text = $(root, 'wc-text').value;
    var words = text.trim() ? text.trim().split(/\s+/).length : 0;
    out.textContent = 'Words: ' + words;        // textContent only — never innerHTML for user data
  }
  root.addEventListener('input', update);
  update();                                     // always render initial state
};
```

**Conventions (rules.md §3):**
- Element IDs prefixed per tool (`wc-`, `mt-`, `og-`…) so pages never collide.
- Classic script, no ES modules — the site must also work opened from disk.
- All dynamic output via `textContent` / `createElement`.

**Optional — the "analyze your page" panel:** every tool page automatically gets an "Analyze your own page first" panel (URL box + paste-HTML fallback). It reads the live page and can pre-fill your tool's inputs and show a personalized fix list. To wire a new tool into it, add an `APPLY[slug]` entry in `src/runtime/inspect.js` (and a `tipFor` case) — the panel mounts itself; no markup needed. Tools that own a native URL box (like the two crawler/ranking tools) are listed in `SKIP_PANEL` there. All panel/audit copy lives in `src/data/inspect.js` and is injected at build time.

### 3. Rebuild and verify

```bash
node build.mjs
```

Confirm the build warns nothing, then test in a browser before declaring it done (rules.md §6): empty input, real input, weird characters, mobile width, copy button.

**Pre-ship checklist for every tool (rules.md §2):** working logic + edge cases · H1 pattern · title/description limits · ≥2 content sections · 3–5 FAQs with schema · copy button on every output · mobile + keyboard operable · listed on homepage + category + related sidebar · in sitemap (automatic).

## Deploying to Cloudflare

### Path A — Workers (the current pipeline: GitHub → `npx wrangler deploy`)

`wrangler.jsonc` is committed, so wrangler never runs its interactive setup wizard on the build server — the deploy is one command.

- **Build command:** `node build.mjs` · **Deploy command:** `npx wrangler deploy`
- `wrangler.jsonc` sets: Worker name `tools4market`, entrypoint `worker.js`, static assets from `dist/` bound as `env.ASSETS`, `html_handling: auto-trailing-slash` (so `/tools/slug/` → `/tools/slug/index.html`), `not_found_handling: 404-page` (branded 404).
- **One Worker = frontend + backend:** `worker.js` serves the static site through the ASSETS binding and routes `GET /api/fetch?url=…` to the shared proxy handler in `functions/api/fetch.js` — same origin, so no CORS and no API keys.
- After the first deploy, attach the custom domain: Worker → **Settings → Domains & Routes → Add Custom Domain** → `www.tools4market.online`.
- **Apex → www 301** (Workers Static Assets reject host-level rules in `_redirects` — error `100324`): do it at the **zone** level — Cloudflare → **Rules → Redirect Rules → Single redirect**:
  - If: `Hostname equals tools4market.online`
  - Then: **Dynamic redirect**, status `301`, target `concat("https://www.tools4market.online", http.request.uri.path)` (preserves the path), preserve query string.
  - Attach only `www.tools4market.online` to the Worker so the apex never resolves to the site itself (no redirect loop).

### Path B — Cloudflare Pages (alternative)

1. Push this repository to GitHub (repo: `github.com/glixtron/tools4market`; or upload `dist/` directly via "Direct Upload").
2. Cloudflare Dashboard → **Workers & Pages → Create → Pages → Connect to Git** (or "Direct Upload") → select `glixtron/tools4market`.
3. Build settings:
   - **Framework preset:** None
   - **Build command:** `node build.mjs`
   - **Build output directory:** `dist`
4. Deploy. Cloudflare gives you a `*.pages.dev` URL — verify the homepage, a tool page and `robots.txt`/`sitemap.xml` there.
5. **Custom domain:** add `www.tools4market.online` under Custom domains (Cloudflare handles SSL automatically) and point the domain's nameservers at Cloudflare. Add a **Page Rule** `tools4market.online/*` → `https://www.tools4market.online/$1` (301) so www stays the canonical host.

On Pages, `functions/api/fetch.js` is deployed automatically as a Pages Function — no extra config, and the client calls it same-origin.

Any static host works the same way (Vercel, Netlify, GitHub Pages): build `node build.mjs`, publish `dist`.

### Cloudflare: frontend **and** backend in one project

Both layers ship from this single repo to one Cloudflare project — no second service to operate:

| Layer | What it is | Where it comes from | Runs on |
|---|---|---|---|
| **Frontend** | 41 static pages (HTML/CSS/JS, 30 tools) | `dist/` (built by `node build.mjs`) | Cloudflare static assets (global CDN) |
| **Backend** | `/api/fetch` live-URL proxy (SSRF-guarded) | `functions/api/fetch.js`, served by `worker.js` | The same Worker (serverless) — or a Pages Function on Path B |

Because the proxy lives on the same host as the pages, the client can call `/api/fetch?url=…` **without CORS** and without any API key in the browser. The same-origin setup also means one SSL certificate, one cache policy and one deployment to reason about.

**Private repo note:** the repo is private, so the Cloudflare Git integration must be granted access to it — in the Pages project → *Settings → Builds & deployments → Connect to Git*, or on GitHub → *Settings → Installed Apps → Cloudflare Pages → Configure → select `tools4market`*. A private repo that the App cannot see simply won't appear in Cloudflare's repo picker.

**If you later want a separate backend domain** (e.g. `api.tools4market.online`): `functions/api/fetch.js` is plain Workers-style code, so it can be deployed as a standalone Worker (`wrangler deploy`) with `Access-Control-Allow-Origin: https://www.tools4market.online`, and the client would call `https://api.tools4market.online/?url=…`. The current same-origin setup is simpler and free — treat the Worker split as a scale step, not a launch requirement.

### Build-time integrations (env vars)

Everything optional is switched by an environment variable at build time — the repo stays clean and nothing is hardcoded:

| Env var | Effect when set |
|---|---|
| `SITE_URL` | Overrides the canonical origin (defaults to `https://www.tools4market.online`) — used by canonical, Open Graph, JSON-LD, sitemap, robots.txt |
| `SITE_EMAIL` | Overrides the contact address in the Organization JSON-LD |
| `GA_ID` | Injects the GA4 `gtag` snippet on every page (IP anonymisation on) |
| `ADSENSE_CLIENT` | Swaps the `.ad-slot` placeholders for real `<ins class="adsbygoogle">` units and writes `ads.txt` with your publisher id |
| `AD_SLOT_TOP` / `AD_SLOT_CONTENT` / `AD_SLOT_SIDEBAR` | Per-position AdSense ad-unit ids (falls back to one shared slot) |

In Cloudflare Pages: **Settings → Environment variables → Production** (and Preview). Example: `GA_ID = G-XXXXXXXXXX`, `ADSENSE_CLIENT = ca-pub-0000000000000000`.

### Integration files the build emits

| File | Purpose |
|---|---|
| `dist/_headers` | Cache policy (`/assets/*` immutable 1y, HTML revalidate 5 min) + security headers (nosniff, referrer-policy, frame-options, permissions-policy) |
| `dist/_redirects` | Comment-only on Workers (host-level redirects are rejected with error 100324). Set `SITE_REDIRECTS_PAGES=1` to emit the apex→www rule when deploying to Pages; on Workers use a zone-level Cloudflare Redirect Rule instead |
| `dist/manifest.webmanifest` | PWA/installability + mobile theme colour, with 192/512 icons |
| `dist/ads.txt` | AdSense publisher id (written only when `ADSENSE_CLIENT` is set) |
| `dist/robots.txt`, `dist/sitemap.xml` | Crawl directives + the 40-URL sitemap, both auto-pointed at `SITE_URL` |
| `functions/api/fetch.js` | The backend route — deployed as a Pages Function on Path B, or served by `worker.js` on Path A |


### The `/api/fetch` proxy (live URL checks)

`functions/api/fetch.js` is a **Cloudflare Pages Function** — it deploys automatically with the site (no extra config, free tier 100k req/day, no API keys in the browser). It lets the client-side tools read an arbitrary page despite CORS, which powers the **"Analyze your own page first"** panel on every tool plus the **Web Crawler Audit** and **SEO Ranking Score** tools.

- **On Cloudflare Pages:** the proxy is live automatically → paste any URL and the tool reads the real page.
- **On another static host / `file://` preview:** the endpoint 404s, so the tools fall back to a direct browser fetch (works for CORS-open sites) and then to **paste-HTML** — the same analysis, run entirely in-browser with nothing uploaded. Tools never break; they just switch to paste mode.

If you deploy to a non-Cloudflare host and want live URL checks, port `functions/api/fetch.js` to that host's equivalent serverless function (Vercel/Netlify functions) — it is the only backend file in the project.

### ⚠️ Before deploying for real: update the site URL

`SITE.url` in `build.mjs` is a placeholder. Every canonical, Open Graph, schema and sitemap URL is derived from it:

```js
const SITE = {
  name: 'Tools4Market',
  url: 'https://www.tools4market.online',
  tagline: 'Free Marketing, SEO & AI-Search Tools',
  email: 'hello@tools4market.online',
};
```

```bash
grep -rn "TODO-DOMAIN" .     # find every placeholder before launch
```

Update `url` and `email` to the real domain, then **rebuild** — wrong canonicals + wrong sitemap URLs tank indexing.

## Monetization: AdSense insertion points

Ad slots are **pre-positioned placeholders** (`.ad-slot`) on every tool page — top banner, below content, and desktop sidebar — with layout already reserved so live ads cause zero CLS. Nothing may ever sit inside the tool interaction area (rules.md §5).

To go live after AdSense approval, edit **one function** in `build.mjs`:

```js
const adSlot = (label) => `<div class="ad-slot" role="complementary" aria-label="Advertisement space">Ad space — live after AdSense approval${label ? ' · ' + label : ''}</div>`;
```

Replace its body with the real unit, keeping the wrapper so the reserved layout still applies:

```js
const adSlot = (label) => `<div class="ad-slot">
  <ins class="adsbygoogle" style="display:block" data-ad-client="ca-pub-XXXXXXXXXXXXXXXX"
       data-ad-slot="XXXXXXXXXX" data-ad-format="auto" data-full-width-responsive="true"></ins>
</div>`;
```

Then add the AdSense loader once in the `<head>` of `layout()` in `build.mjs`:

```html
<script async src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-XXXXXXXXXXXXXXXX" crossorigin="anonymous"></script>
```

Also update the **Privacy Policy** in `src/data/policy.js` with the real publisher ID once approved (rules.md §5). Apply for AdSense only after: 20 tools + policy pages + 20–30 original articles + 50–100 daily visitors.
